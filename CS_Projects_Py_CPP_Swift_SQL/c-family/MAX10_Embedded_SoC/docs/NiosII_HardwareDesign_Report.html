Procedure/Description of Test:

In this module, the primary objective was to design, integrate, and compile the underlying hardware architecture of a System on a Chip (SoC) using Platform Designer (Qsys). The system features a Nios II soft processor, on-chip RAM, a JTAG-UART interface, and various Avalon Memory-Mapped (Avalon-MM) peripherals. After generating the Qsys system and synthesizing the VHDL top-level entity in Quartus Prime, the resulting .sof file was programmed into the MAX 10 FPGA.

Observations:

Upon programming the FPGA, the device was successfully configured without any hardware errors. However, because this module focuses exclusively on the static hardware layer (without loading the compiled C executable code), the system did not perform any interactive, visible actions. Internally, the Nios II processor, VGA controller, memory, and PLLs are completely mapped and initialized in the hardware fabric, waiting in an idle state for software commands.

Data:

The design compiled cleanly. The static mapping of memory addresses for all Qsys components was verified, ensuring no overlaps in the Avalon-MM bus address space. TimeQuest Timing Analyzer confirmed the critical paths met timing requirements.

Results:

  • Logic Utilization: ~25% (12,481 Logic Elements)

Questions:

  • 1. What is the purpose of the Avalon Memory-Mapped Clock-Crossing Bridge?
    The purpose of the Avalon Memory-Mapped Clock-Crossing Bridge is to allow safe and reliable communication between different clock domains within the same SoC architecture. In complex designs like this one, peripherals often run at different frequencies than the main processor core (for instance, the Nios II might run at 100 MHz while a specific peripheral operates at 50 MHz). The clock-crossing bridge handles the synchronization of data, address, and control signals across these asynchronous boundaries using FIFOs and synchronizers. This prevents metastability and ensures that data is safely transferred without corruption or timing violations.
